# OC Shimeji 對標評估與全面重構計畫

本文件與 `docs/v17-roadmap.md`（背景生活、觀察模式、每日結算的關係，你已同意五項建議）合併成一條路線：

- **MVP**：17.1–17.4，以背景生活為核心；
- **階段二**：18.x，桌寵重構與介面重做；
- **階段三**：19.x，內容、世界與分享。

**兩個前提（CLAUDE.md 已定案，不更動）**

- **美術方向**：方案 G「晴日島 3D」——3D 世界（正交、俯角 50°）＋ 2D 角色、2D 介面、2D 桌寵。下面的「視覺重做」是在這個方向**之內**重做介面語言與質感，不是換一個新方案。
- **介面風格**：整個 App 只有一種介面風格。新的設計語言會**整個取代**「島日和」，不會變成可切換的第二種風格。
- **對標作品**：只吸收設計原則，不使用其角色、Logo、介面圖形、地圖或素材。

## 第一部分：對標分析與功能缺口

### 1. 四款對標作品的設計核心

| 作品 | 核心 | 值得學的原則 |
|---|---|---|
| **The Sims 4** | 玩家導演一個家庭：需求、情緒、技能、職業、抱負、建造 | ① 情緒是「有原因的」（每個情緒附來源與持續時間）；② 圓餅選單依情境列出動作，並顯示「為什麼現在可以／不可以」；③ 動作佇列可見、可取消；④ 建造模式與生活模式明確分開；⑤ 長期目標（抱負）把短期行為串起來 |
| **inZOI** | 寫實的城市生活模擬：細緻的外觀編輯、城市裡大量居民自主生活、角色的「想法」可以讀 | ① 角色的內心（想法、動機）攤開給玩家看；② 自主生活的密度高（街上一直有事發生）；③ 創作工具強（外觀、物件自訂） |
| **集合啦！動物森友會** | 現實時間的島嶼生活：每天回來看看，收集、佈置、和居民說話 | ① **現實時鐘＋每日更新**讓「每天回來」有意義；② 介面極少、世界優先，手機 App 承載功能；③ 每次互動都有聲音、動畫、文字的回饋（「手感」）；④ 季節與節日改變整個島；⑤ 居民台詞量極大、很少重複 |
| **朋友聚會（Tomodachi Life 系列）** | 觀察住民自己過日子：他們戀愛、吵架、做夢、出各種小問題來找你 | ① **觀察的樂趣**：不用操作也有戲看；② 住民主動來找你，帶著具體的小問題（想吃什麼、想要什麼衣服、和誰吵架）；③ 荒謬又溫柔的小劇場（夢、演唱會、告白）；④ 關係變化是大事件，有演出 |

參考作品《角色觀察屋》的分析在 `docs/v17-roadmap.md` 第〇節：
- 背景生活；
- 今日時間線；

## 第二部分：重構藍圖

### 一、背景生活與「故事層」（MVP 的核心）

詳細規格在 `docs/v17-roadmap.md` 第一到三節。這裡列模組設計。

**模組**：

| 模組 | 職責 | 介面 |
|---|---|---|
| `OC.Away`（`life/away17.js`） | 離開時的推算 | `away.run(fromMs, toMs)`：同一份存檔、同一段時間，結果一定相同；前 72 小時每 10 分鐘一步，之後每天一步；最多 30 天 |
| `OC.Chronicle`（`life/chronicle17.js`） | 唯一的事件紀錄（時間線） | `log({ t, who[], place, kind, text, weight, key })`；所有系統（Brain、Will、Topic、Health16、Career16、Arcs…）只往這裡寫；一天一個區塊，保留 60 天，收藏另存 |
| `OC.Digest` | 把時間線變成故事 | 「你不在的時候」、每日結算卡、名場面（依 weight 與稀有度挑）、角色日記（從台詞資料挑句子，不用 AI） |
| `OC.Replay` | 回放 | 文字回放 1×–1024×；3D 重演最高 64×，只有位置與動作，**不改資料** |
| `OC.Settle` | 每天結算 | 關係門檻（好感／心動、保持 2 天）、紀念日、明天的預告 |

**規則**：

- 離開期間會發生：關係、回憶、技能、人生大事。
- 離開期間不會發生：星幣、物品（你同意的建議 2）。
- 背景推算不送 `OC.Progress` 事件，所以任務和成就不會在離開時完成。
- 事件與關係變化會發生，並寫進時間線。

### 二、桌寵系統全面重構

#### 2.1 目標

從「會到處走的貼圖」變成「住在你桌面上的那個角色」：
- 有目標、有東西可以用；
- 知道島上發生了什麼；
- 桌面發生的事會回到遊戲變成回憶。

#### 2.2 分層狀態機（取代現在的單層 `PetBrain`）

```
PetMind（決定「想做什麼」，每 2–6 秒或事件觸發）
  └ 目標：休息／找東西吃／玩／找你／找另一隻／發呆／去某個桌面物件／依作息睡覺
     輸入：遊戲快照（需求、情緒、個性、作息、生病、上班上學、今天的大事）＋桌面狀態（物件、其他桌寵、螢幕方向、時間）

PetPlanner（把目標變成一串動作）
  └ 例：「想吃東西」→ 走到食物碗 → 坐下 → 吃（3 秒）→ 滿足的表情 → 回報遊戲

PetMotion（現有 PetBrain 的運動層：走／跑／跳／爬／倒吊／掉落／偷看，保留並加測試）

PetReact（最高優先、可以打斷：被點、被摸、被抓、被丟、通知、另一隻來找）

PetFace（表情與小動作層：眨眼、看向手指、情緒小動作，疊在任何動作上）
```

- 每一層都是純 Kotlin（`core:pet`），有單元測試；原生視窗層仍然只負責顯示（14.0 的規則）。
- **個性與情緒怎麼驅動**：
  - `PetMind` 的目標分數＝需求權重 ×個性係數 ×情緒係數 ×作息係數，和遊戲的 Utility AI 同一套思路，係數表由遊戲匯出（`config.json` 的 `mind`）。
  - 例：活潑的「玩」×1.4；害羞的「找你」×0.6、「偷看」×1.5；生病時「休息」×2.5、「跑」= 0。
  - 例：今天剛和誰吵架，看到那隻桌寵就走開。
- **可解釋**：長按桌寵的選單第一行寫出「現在想：想吃東西（肚子有點餓、平常這時候吃點心）」。

#### 2.3 桌面互動物件

| 物件 | 互動 | 回到遊戲 |
|---|---|---|
| 食物碗 | 放進背包裡的食物（從選單拖），桌寵餓了會去吃 | 經 `events.jsonl`，物品走 `OC.Tx` key `pet:<事件>` |
| 小床／坐墊 | 依作息去睡、累了去躺 | 「在桌面上睡了午覺」回憶 |
| 玩具球 | 可以丟（拖曳拋出），桌寵會追 | 玩的回憶、心情 |
| 盆栽 | 每天澆水，會長大（現實天數） | 島報與回憶 |
| 留言板 | 桌寵寫下今天島上的一件大事（來自時間線） | — |
| 小信箱 | 島上有信（`OC.Budget.mail`）時會亮，點了打開遊戲 | — |

- **技術限制（必須遵守）**：
  - 每個物件是自己的小視窗，只和物件一樣大；
  - 不得有全螢幕透明層；
  - 所有視窗 `FLAG_NOT_FOCUSABLE`；
  - 同時最多 4 個物件。
- 物件位置記在原生設定，桌寵用物件位置當作目標。
- 桌面物件是**只在桌面上用的物品**，從遊戲背包「擺到桌面」，收回時回到背包，經 `OC.Tx`，不會複製。

#### 2.4 桌寵模式

| 模式 | 行為 |
|---|---|
| 陪伴（預設） | 照上面的分層狀態機 |
| 安靜 | 只坐或睡，不說話、不發聲、不爬，觸控穿透可選 |
| 專注 | 番茄鐘期間只在角落陪你工作，休息時間才出來 |
| 熱鬧 | 多一點小動作和台詞；多隻時更常互動 |

依時段自動切換（例如晚上 11 點後安靜）。

#### 2.5 自訂與擴充：桌寵行為包

- 格式 `.ocpet`（JSON＋影格），也可以放在 `.ocpack` 裡：
  - 新動作（影格＋時長）；
  - 觸發條件（目標、情緒、時段、物件）；
  - 台詞分類；
  - 音效（遊戲合成的 WAV）。
- **只有資料、沒有程式碼**，和 16.3 事件腳本同一個原則：匯入時驗證，不合格的不能「看似成功」。
- 遊戲裡的「桌寵中心」加「行為」分頁：開關每一種行為、調頻率、預覽。

#### 2.6 和遊戲的雙向同步

- **遊戲 → 桌寵**：
  - 快照多帶：今天的大事三則（時間線）、未讀信數、和其他桌寵的關係變化、作息的下一件事；
  - 背景推算預測的「接下來的大事」，用來在桌面上演一個小預告。
- **桌寵 → 遊戲**：
  - 吃、玩、睡、被摸、被丟、和另一隻互動，都寫進遊戲的時間線，標「在桌面上」；
  - 不給星幣，物品只經 `OC.Tx`。

### 三、UI／UX 與視覺打掉重來

#### 3.1 新的視覺方向：「晴日島 3D」之內的「島的手帳」

- **概念**：介面像角色們的生活手帳——紙、貼紙、手寫標籤、膠帶，世界是主角，介面是貼在旁邊的筆記。
- **取代「島日和」**：
  - 仍是**唯一一種**介面風格；
  - 白天、夜晚兩個調色盤，形狀與元件相同；
  - 所有顏色仍只從 tokens 來。
- **世界**：
  - 3D 不變，加強「玩具微縮感」：景深在「高」品質、柔和的接觸陰影、季節色調；
  - 角色看板放大 15%，遠景加輪廓光，在畫面上更容易看清楚；
  - 這只是參數調整，不改方向。
- **字**：維持開放授權字體；字級減為 5 級（12／14／16／20／28），每個畫面最多用 4 級。

#### 3.2 介面架構原則

1. **三層，不混用**：
   - **世界層**：角色、泡泡、時間線浮標；
   - **HUD 層**：最多 6 個元件——名牌、時間天氣、觀察開關、時間線把手、工具把手、任務卡；
   - **頁面層**：口袋手機與全螢幕頁。
   - 卡片、提示只能在自己的層，不得蓋住下一層的按鈕（17.0 修過的問題變成規則）。
2. **觀察優先的主畫面**：
   - 打開 App 先看到世界和「正在發生」的事；
   - 操作從點角色或物件開始（點選 ≠ 執行，15.0 的原則保留）。
3. **口袋手機重排**：
   - 一排「常用」（可自訂，最多 4 個）；
   - 加上 5 個資料夾：生活（住處、工作學校、行程、健康）／島嶼（地圖、商店、島報、圖鑑）／收藏（回憶、相簿、成就）／創作（工坊、工作室、設計亭）／工具（桌寵、提醒、設定）；
   - 一頁不超過 12 個圖示。
4. **一種選單**：
   - 角色、物件、地面都用同一個環狀選單（16.4 已有，物品卡片也要改過來）；
   - 每個項目顯示「大概的反應」與「為什麼不行」。
5. **通知只有三種**：
   - 立刻（需要你回答：請求、事件提問）→ 經打擾預算；
   - 稍後（信箱）；
   - 時間線（不打擾）。
   - 成就、任務完成合併成一張「＋N」。
6. **每頁一個主要按鈕**，觸控 ≥ 48dp，空狀態一定寫出「下一步可以做什麼」。

#### 3.3 動畫與微互動規範

| 類別 | 規範 |
|---|---|
| 時長 tokens | `--t-press` 80ms、`--t-fast` 160ms、`--t-base` 240ms、`--t-page` 320ms、`--t-spring` 420ms；超過 500ms 的只用在演出 |
| 曲線 | 進入用 `--spring`（輕微回彈）、離開用 `--ease-in`（不回彈）、狀態切換用 `--ease-out` |
| 按下 | 每個可按的東西：下沉 2.5px＋陰影縮短＋輕觸覺＋短音效（同一個元件 `press()` 處理，不再各寫各的） |
| 出現 | 卡片與視窗：由小 4% 放大＋淡入；清單項目錯開 30ms |
| 回饋三件套 | 得到東西、關係變化、完成目標：動畫＋聲音＋一句角色的話，三者同時 |
| 減少動態 | 系統設定或遊戲設定打開時：位移改淡入、沒有回彈、沒有粒子 |
| 效能 | 常駐元件不用 `backdrop-filter`；3D 畫布與全螢幕常駐層不用 `filter`／`mix-blend-mode`（14.1 的規則） |

#### 3.4 新舊過渡策略

- **逐頁替換，沒有使用者看得到的開關**（規則：只有一種風格）。
- **第 1 步：新 tokens 與元件庫**：
  - 新增 `css/tokens2.css` 與 `ui/kit2.js`（按鈕、卡片、清單列、分段、標籤、空狀態、頁首、資料夾）；
  - 舊頁面暫時對應到新 tokens 的近似值，畫面不會「半新半舊」得太明顯。
- **第 2 步：一次一組頁面**：
  - 順序：主畫面與 HUD → 口袋手機 → 角色與工作室 → 生活類頁面 → 商店與背包 → 設定；
  - 每組替換完：逐頁截圖（淺色＋深色、360／393／412 三種寬度）、真實觸控測試、舊的 CSS 規則刪掉。
- **第 3 步**：全部換完，刪除 `島日和` 的舊規則，tokens 合併回單一檔案。
- 存檔與資料**完全不受影響**（只換介面）。

### 衡量「變好了」的方法

- **電腦上能量的**：
  - 背景推算時間；
  - 時間線每天的事件數與重複率；
  - 台詞重複率（同一句 7 天內出現次數）；
  - 頁面截圖檢查（沒有元件互相遮蓋、觸控區 ≥ 48dp）；
  - 繪製呼叫數。
- **只有你能量的**（📱，我會在每版報告附一張檢查表）：
  - 手機上的 FPS、耗電；
  - 桌寵與通知是否正常；
  - 「隔天打開想不想看『你不在的時候』」。
