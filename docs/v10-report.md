# OC Shimeji 10.0（0.10.0-alpha）美術與體驗重構紀錄

> 依你的要求，以 0.9.0 為基礎重建整體美術方向與介面語言，並實際整合進 App（不是提案或示意圖）。
> 狀態：✅ 已在本環境實測（Chromium 手機模擬，393×852，淺色＋深色）／📱 需實機／◐ 部分完成／✗ 未完成。
> 存檔 schema 不變（v7）；角色、存檔、設定都不受影響。設計規格：`docs/design-system.md`。

## 一、方向（先建立系統，再重製畫面）
**暖陽照著的小島（世界）＋ 白瓷玩具般的介面（UI）**。參考圖的優先順序最高：
- 小島 HUD 圖 → HUD 版面（頭像名牌、天氣時間膠囊、右側工具列、任務卡、白色大導覽列、紅點）。
- 低多邊形世界圖 → 浮在世界上的白色圓角元件、物品坐在圓形底座上、膠囊工具列。
- 粉彩 App 圖 → 雲邊天空頁首、圓形分類圖示、長春花紫。
- 大頭角色圖 → 角色的「軟塑膠」體積感（角色仍是 2D 看板，依已選定的方向 G）。
- 動物森友會／Tomodachi Life／曠野之息 → 只吸收原則：柔和圓潤、按下有手感、角色帶情緒的回饋、自然的光與世界動態、低學習成本。
- **沒有使用任何作品或參考圖的角色、Logo、圖示、介面圖形或素材**；貼紙圖示、配色、版面都是原創。

- 測試中發現並處理：
  - 第四階段測試 12（常駐 HUD ≤ 6）抓到 HUD 有 8 個常駐元件 → 拿掉重複的齒輪與互動鈕（見二、HUD 取捨）。
  - 第四階段情境 3（兩個 OC 聊天、一起坐長椅）在機器負載很高時偶爾失敗。**同樣的負載下，用 0.9.0 的程式交錯執行也會失敗**（3c、3d），所以不是 10.0 造成的；原因是走路用真實時間、在軟體渲染下幀率很低時，計畫會在走到之前逾時。為此仍做了兩件對手機也有益的事：省電模式完全關閉毛玻璃模糊與裝飾性循環動畫、光暈混合層只在調色開啟時存在。測試失敗時現在會印出兩個 OC 的狀態，方便日後追查。
- 效能：本環境是軟體渲染（SwiftShader），fps 數字不代表手機；在這裡量到「關掉毛玻璃」能讓幀率提高約三成，所以省電模式把它關掉。實機數字 📱。

## 五、需要實機（📱）
- `backdrop-filter`（HUD 毛玻璃、景深）與 CSS `linear()` 彈簧在各家 Android WebView 的效能與外觀；已設計退回：省電模式關閉調色與景深、平衡模式關閉景深，舊 WebView 自動用三次貝茲曲線。
- 觸覺強度、音效與畫面節奏的整體手感、120Hz 裝置上的彈簧動態。
- 桌寵泡泡、小工具、啟動畫面的新色在不同桌布上的對比。

## 六、尚未完成（✗／◐）與原因
- ✗ **3D 模型重新建模**（建築、樹、家具改成更圓潤的低多邊形造型）：這次只改了光、調色、景深與環境生物；重做模型需要逐一調整碰撞與佈置，留到下一輪。
- ◐ **動畫工作室、繪畫工坊、角色編輯器**：已套用新元件樣式，但版面沒有重新設計。
- ◐ **角色動作**：加了跳躍的預備與回彈、玩具光影；更多新動作（例如走路的重心起伏誇張化、各種情緒的全身表演）沒有在這一輪重做。
- ✗ 角色改成 3D 玩偶：與已選定的方向 G（角色一律 2D）衝突，沒有做。
- 參考圖中的「鑽石／星星等其他貨幣」「拍照模式」：遊戲沒有這些系統，**沒有做假按鈕**；工具列只放真的功能（背包、鏡頭、佈置）。

## 你回報的兩個問題
**1. 和角色互動之後角色會卡住** — 找到四個實際原因（都已修正並有自動測試）：
| # | 情況 | 原因 | 修正 | 驗證 |

| 2 | 和 A 聊天時又開了另一段對話 | 新對話直接覆蓋舊對話，舊對話的結束回呼（放開 A）永遠不會執行 | 開新對話前先正常結束舊的 | `tests/v10` 3 ✅ |

**2. 打開環狀選單太突兀** — 重新設計成一個連續的動作：

角色會停下來、轉向你、輕輕彈一下（睡著的不會被吵醒）；選單跟著角色；其他角色的泡泡暫時變淡；選擇時被選的按鈕放大、其他收回；關閉時倒著播放。
