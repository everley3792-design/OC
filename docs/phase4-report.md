### 測試過程中發現並修正的問題
- 操控中的角色只能做原地小事 → 會餓壞：現在你 40 秒沒操作且需求嚴重不足時，牠會自己去吃飯／睡覺。
- 餓壞或睏壞的 OC 仍被拉去聊天 → 照顧自己優先，也會婉拒邀請；剛聊過會先做別的事（避免一直聊天）。
- 床的對齊：鎖定動作阻擋了最後的對齊移動 → 先對齊再播放動作。
- 兩個 OC 同時邀請同一個對象 → 被邀請中的 OC 不再接受其他邀請。
- 結束活動後站在原位子上、另一個 OC 走到同一點 → 離開座位／攤位時走到空的位置；選位置時檢查「有人站著／正要走過去」。
- 事件走位沒有檢查空位 → 事件也只走到空的位置。
- 太餓還去睡 → 2 分鐘後餓醒再睡的循環 → 太餓睡不著（先吃飯）。
- 主迴圈卡頓（軟體繪圖一幀 > 3 秒）時循環時鐘遺失時間 → 卡頓以步進補算；開機時間不再算入遊戲時間。
- 換天時把前一天的普通回憶立刻忘掉 → 「最近」回憶保留兩個遊戲日。
- 聊天結束時原本的活動已超時 → 立即結束。
- 「關閉同類建議」只擋新的 → 也收起已在等待的同類建議。
- 編輯器暫停的解除用的是被限制的幀時間（慢手機會延遲數秒）→ 改用現實時間。
- 世界的對話泡泡會蓋在頁面上 → 頁面開啟時隱藏、圖層在頁面之下。
- `world.resize()` 在 3D 初始化前被呼叫會報錯 → 加上防護。

## 尚未驗證／已知限制（誠實標示）
- 🟡 **實機**：本環境沒有 Android 裝置或模擬器。需要在手機上確認：多個 OC 同時生活時的 fps 與電量、WebView 背景／前景切換時的離線補算、長時間開著的記憶體、觸控拖曳 OC 的手感。
- 🟡 **懸浮桌寵**：原生桌寵仍只播放 6 組動作，尚未讀取 `life` 欄位或 `petContext`（App 情境台詞需要原生端與權限設計，屬於後續階段）；桌寵驗證清單仍未在實機執行。
- ⚠ **時間尺度**：移動與對話泡泡是現實時間；在 ×10 速度下，一段聊天約等於一兩個遊戲小時。需求與活動的結果不受影響（測試 9），但看起來 OC 在高速時「花很多時間聊天走路」。
- ⚠ **音效**：事件可以記錄 `sound` 步驟，但遊戲仍沒有音訊系統（設定中標示未開放）。
- ⚠ **居民**：島上的居民栗子、小空（第二階段 NPC）仍使用原本的對話與散步，尚未接上生活引擎；只有玩家的 OC 有完整的生活模擬。
- ⚠ **內容量**：229 句內建台詞、14 個事件、14 種活動、14 種社交；長時間遊玩仍可能聽到重複台詞（冷卻會先用完所有可選台詞）。玩家可以自訂與匯入更多。
- ⚠ 預設時間仍是「現實」（舊存檔與新存檔相同）；在現實時間下活動以分鐘到小時計，想快速看到生活變化可在設定中切換「循環」。
- ⏭ 擴充地圖、商店／經濟、釣魚、種田、旅行：依指示未做。
