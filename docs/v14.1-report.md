# 14.1／14.2（0.14.2-alpha）修正卡頓、做完 14.0 沒做的

要求：繼續做完還沒做的；整個遊戲都異常卡頓，請修正。

**先說清楚**：這個環境沒有手機，也沒有真的 GPU（測試用的是軟體渲染，約 2–4 fps，所有畫面都「慢」）。所以我**量不到手機上的幀率，也無法證明修正後在你的手機上不卡**。能做的是：用 CPU profiler 和繪圖狀態找出「每一幀都在做、而且在手機 WebView 上已知很貴」的東西，把它們拿掉或改成便宜的做法，並用測試確認它們真的不在了。修正是否足夠，要你裝上 0.14.1 實際試。

## 一、卡頓：找到什麼、怎麼改

| 找到的問題 | 為什麼貴 | 修正 |
|---|---|---|
| 3D 畫布上套了 CSS 濾鏡 `filter: saturate() contrast()`（「平衡」與「高」預設開啟，用來調色） | 合成器每一幀都要把整個畫面先畫到離屏緩衝、跑一次濾鏡再貼回來；在手機 WebView 上這通常是最重的一項，還可能讓畫布離開直接合成的快速路徑 | 調色改在**著色器**裡做（接在每個內建材質片段著色器的最後，幾個運算），畫面上的 CSS 濾鏡拿掉。三種效能模式的調色現在一致 |
| 光暈層用 `mix-blend-mode: soft-light` 蓋在整個畫面上 | 混合模式會強制再開一個全螢幕的離屏緩衝 | 改成一般的半透明層（調低不透明度） |
| 路燈的點光源在**白天**也在場景裡（亮度 0） | 亮度 0 的光仍然是「一盞光」：每個受光表面的每個像素都要算它（小島 3 盞） | 白天完全關掉（`visible = false`），晚上才打開；兩種狀態的著色器在載入地點時先編好，黃昏與清晨只是切換已存在的程式 |
| 每次編譯著色器都向驅動要錯誤紀錄（three.js 預設） | 這會強迫著色器當場編譯完成，東西第一次出現時畫面頓一下；profile 裡這一項佔了啟動後 12 秒中的 1.1 秒 | 關閉 `checkShaderErrors`，並在載入地點（轉場淡出的後面）一次把該地點的著色器編完 |
| 陰影貼圖每一幀重畫整個場景；所有模式都用柔邊陰影 | 陰影那一遍是另一半的繪製呼叫；柔邊（PCF Soft）每個像素取樣很多次 | 「高」以外的模式改成每兩幀更新一次陰影貼圖、用一般的硬邊 PCF；「高」維持每幀＋柔邊 |
| HUD 每一幀都重新組一次比對字串（名稱、心情、任務、時間…） | 每秒 60 次字串組合與比對，內容其實幾分鐘才變一次 | 每秒 5 次 |
| 對話泡泡每一幀都寫 `left/top`（即使沒移動） | 每幀觸發版面計算 | 位置真的變了才寫 |
| HUD 頭像每 66 ms 重畫一次 | 小畫布，但常駐 | 改為 120 ms |

另外加了一個保護：**「平衡」模式會看自己的幀率**——連續三秒低於 42 fps 就把解析度降一級（同時縮小陰影貼圖、草量與角色貼圖），最多降兩級，不會一直降；短暫掉幀不算；「高」與「自訂」不會被自動調整；重新選一次模式或重開 App 會回到原本的設定。

原生端：WebView 明確使用硬體圖層，並在遊戲顯示時要求前景優先權（兩者都是提示，不支援的裝置照常運作）。

**這一輪之前就做的**（14.0）：靜態模型依材質合併，小島的繪製呼叫 557 → 約 250。

**沒有改、但可能仍然有影響的**：
- 「高」模式的景深是兩條 `backdrop-filter` 模糊帶，本來就很貴，保留給效能夠的裝置；卡的話請用「平衡」或「省電」。
- 角色看板的貼圖：姿勢改變時重畫（待機每秒 4 次、動作中每秒 10 次），每個角色一張 256–512 px 的畫布上傳到 GPU。三個角色以內我判斷可以接受，但沒有在手機上量過。
- 桌寵服務同時在執行時，會和遊戲搶 CPU／GPU。

## 一之二、14.2：回報「平均只有 20 幀上下」之後

**我不知道這個數字是在哪一版量到的**（0.14.0 還是 0.14.1），也還不知道手機型號，所以下面仍然是「把已知會拖慢手機的東西拿掉」，不是對症下藥後的確認。

這一輪重新量了主執行緒每一幀花在哪裡：遊戲邏輯（生活模擬、AI、事件、音效…）合計不到 0.5 ms，幾乎全部時間都在 3D 繪製與它相關的上傳。所以這一輪只動繪製：

| 找到的問題 | 為什麼貴 | 修正 |
|---|---|---|
| 角色看板的畫布是 GPU 畫布 | 姿勢一變就要把畫布上傳成 WebGL 貼圖；GPU 畫布得先從 GPU **讀回**記憶體才能上傳，在手機上一次可能要幾十毫秒，三個角色每秒十幾次 | 建立畫布時就要求 CPU 畫布（`willReadFrequently`），上傳變成單純的複製。這裡量到的上傳次數與幀數：每幀 2.17 次 → 1.02 次，同樣 15 秒內畫出的幀數 87 → 110 |
| 一幀內可能同時重畫三個角色 | 重畫＋上傳集中在同一幀，造成頓一下 | 一幀最多重畫兩個，其餘等下一幀；你操控的角色永遠不用等 |
| 待機時每秒重畫 4 次 | 待機的呼吸是用網格縮放做的，不需要這麼常重畫貼圖 | 每秒 2 次 |
| 花圃的每一朵花是 3 個獨立的網格（為了讓每朵各自搖） | 小島 4 個花圃共 160 多個繪製呼叫，佔全部的三成；每個呼叫在手機 WebView 上都有固定的 CPU 成本 | 一個花圃的花合成一叢（每種顏色一個網格），整叢一起隨風搖；石頭邊框併入花圃。**小島的繪製呼叫：約 250 → 約 140**（14.0 之前是 557） |
| 自動降級最多只到「解析度 ×1、陰影 512」 | 如果這樣還是跟不上，就一直卡著 | 多一級：關掉陰影那一遍（等於少畫一半）、草與點光源 |
| 14.1 我加了「WebView 明確使用硬體圖層」 | 這會讓整個 WebView 先畫到一張額外的貼圖再合成，可能反而更慢——是我加錯了 | 拿掉，回到預設 |

**新增：看得懂的效能數字。** 「設定 › 顯示 FPS」現在會顯示一條：

`23 fps｜每幀 31.0ms（繪製 24.0）｜角色重畫 14/秒｜呼叫 140｜×1.00｜陰影 512｜降級 2`

如果 0.14.2 還是卡，請把這一行拍給我（最好是在小島上站著不動時，和走路時各一張），加上手機型號。從它可以直接看出方向：
- 「每幀」接近或超過 30 ms、而且大部分是「繪製」→ 繪製呼叫或驅動是瓶頸，要繼續合併模型、或再降陰影。
- 「每幀」只有幾 ms、fps 卻很低 → 主執行緒是閒的，瓶頸在 GPU（像素量、透明疊加）或 WebView 的合成，要往解析度、特效、畫布合成方式查。
- 「角色重畫」很高 → 還要再降角色貼圖的更新頻率或解析度。
- 「降級」已經是 3 還是卡 → 自動降級救不了，問題不在我調的這些東西上。
