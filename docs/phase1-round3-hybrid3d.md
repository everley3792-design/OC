## 規則變更（取代「完全禁止 3D」）
| 項目 | 新規則 |
|---|---|
| 世界（地形、建築、樹木、道具、水、光影） | **可以使用 3D**，但鏡頭**固定**：正交投影、俯角 50°，不旋轉；只允許平移與縮放 |
| 角色（OC、NPC） | **維持 2D**：用 2D rig／逐幀圖畫在「面向鏡頭的看板」上，放進 3D 世界 |
| UI、HUD、所有頁面 | 2D |
| 繪畫工坊、逐幀動畫工作室、玩家素材 | 2D（不需要玩家做 3D 建模） |
| Android 懸浮桌寵 | 2D（同一套 2D 角色素材） |

## 怎麼做到「3D 世界、2D 角色」還完全相容
1. **座標對齊**：地面點 2D `(x, y)` 對應 3D `X = x, Z = (y + 層高) / sin50°, Y = 層高 / cos50°`。在正交 50° 鏡頭下，它會投影回**完全相同的螢幕位置**。所以前兩輪的版面、手指路徑、UI 錨點、角色站位全部可以直接沿用（原型中 E 的所有畫面一行都沒改）。
2. **角色看板**：每個角色每幀用 2D rig 畫進一張畫布貼圖，貼在永遠面向鏡頭的平面上。平面放在角色腳底，所以和 3D 房子、樹木的前後遮擋是正確的。地面上另加一個柔和的圓形陰影。
3. **光影**：太陽／月亮方向光＋半球光、柔和陰影；窗戶與路燈在夜晚發光，並帶點光源。2D 角色會跟著天色染色，不會在夜裡顯得突兀。
4. **玩具微縮感**：畫面上下緣做輕微景深模糊（tilt-shift），黏土般的圓角斜面與低金屬度材質。

## 和 E（純 2D）的差異
| | E · 晴日島嶼（2D） | G · 晴日島嶼 3D（混合） |
|---|---|---|
| 立體感 | 插畫式，靠陰影色塊 | 真實的光影、遮擋、高低差、投影 |
| 日夜／天氣 | 色調疊加 | 真實光源與陰影方向變化，窗戶與路燈發光 |
| 世界製作 | 2D 繪製（或程式繪製） | Blender 建模 → glTF；可烘焙光照 |
| 角色與 UI | 2D | 2D（完全相同） |
| 玩家創作 | 2D | 2D（完全相同） |
| 效能 | 低 | 中（固定鏡頭可烘焙靜態光影；角色只是貼圖平面） |
| 開發成本 | 低 | 中：需要 3D 場景美術與 Android 3D 渲染 |

## Android 技術方案（更新）
- **建議**：保留 Kotlin 單一程式碼庫，世界層改用 **Filament**（Google 的 Android 原生 PBR 引擎，Kotlin/Java API、glTF 載入、陰影、效能佳），UI 仍用 Compose 疊在上方。
  - 場景：Blender 製作 → glTF（.glb），靜態物件烘焙光照貼圖與 AO；日夜以光色＋兩組 lightmap 混合。
  - 角色：2D rig 以 Android Canvas 畫到 Bitmap → 上傳成貼圖 → 看板 quad；或預烘 sprite atlas（省電模式）。
  - 懸浮桌寵：不變，仍是 2D Canvas View，共用同一套角色素材。
- **替代**：若團隊偏好視覺化關卡編輯器，可改用 **Godot 4**（內建 Sprite3D 看板、固定相機、Android 匯出）。懸浮桌寵仍需 Kotlin 外掛實作。
- 模組調整：`render:world` 從「2D SpriteBatch」改為「3D 場景＋看板角色」；`core:*`、`platform:overlay`、`ui:*` 不變。

## 效能模式（3D 世界）
| 模式 | 解析度 | 陰影 | 光照 | 其他 |
|---|---|---|---|---|
| 高畫質 | 原生 | 即時柔和陰影 | 動態＋烘焙 | tilt-shift、海面波動 |
| 平衡 | 原生 | 角色圓形陰影，靜態物件用烘焙陰影 | 烘焙為主 | 海面低頻波動 |
| 省電 | 0.75× 渲染後放大，30fps | 只有烘焙 | 只有烘焙 | 關閉景深、樹搖改為只動樹冠 |

## 誠實說明
- 原型是在雲端無 GPU 的環境中，以 WebGL（SwiftShader 軟體渲染）錄製。正式 App 會在手機 GPU 上以 Filament／Godot 重新實作，畫質與效能需實機調整。
- 3D 模型為程式生成的簡化幾何（圓角方塊、擠出地形、球體樹冠），用來呈現方向。正式版應由美術用 Blender 製作更細緻的造型（磚、瓦、木紋、斜面）。
- 參考圖只用來理解「固定視角 3D 微縮」的效果，沒有使用其素材或造型。
