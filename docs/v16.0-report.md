# 16.0（0.16.0-alpha）先修看得到的

計畫：`docs/v16-plan.md`（玩家確認的 16.0–16.8）。這一版做計畫裡的 16.0：畫質與圖片角色、名牌卡、切換操控、介面直接操作、打擾預算、日曆、存檔 v8。

## 問題 → 原因 → 修正 → 驗證

| 問題 | 原因 | 修正 | 驗證 |
|---|---|---|---|
| 匯入圖片的角色很糊 | 角色畫在固定的正方形小畫布；畫布解析度上限 256–768 且會被效能降級；2048 的原圖一次縮到幾百像素 | **兩段式繪製**（`world.js` `renderWorld`）：世界照 `quality.ratio` 畫進一個渲染目標，複製到畫面（顏色＋深度），角色（layer 1）再用螢幕原本的解析度畫在上面，仍會被樹和牆擋住。大圖先做**一串減半的縮小圖**（`CharRender.mipOf`），最後一步縮小不超過 2 倍。設定「角色畫質：自動／最高」；自動降級不再縮小角色圖片，先犧牲世界。只有 WebGL 2；不支援就維持單段。畫出錯誤時自動退回單段 | v16 1a、1c |
| 放大角色會被切掉 | 畫布大小固定（120 設計單位） | 畫布依角色大小成長（`CharRender.extent`：1–6 倍，每 0.25 一階，看板同步放大）；標記、泡泡高度依角色實際高度（`CharRender.tall`）；點擊範圍跟著長高 | v16 1b |
| 寬高不能分開調整、裁切限制太小 | 只有一個縮放（40–250%）；裁切每邊最多 45% | `frame.sx`／`frame.sy`（20–400%）、整體大小 20–400%、位置 ±150%、裁切每邊最多 90%（對邊加起來不超過 92%）；編輯器新增「大小框」：拖右邊＝寬、上邊＝高、右上角＝整體 | v16 1b（資料）；操作方式見未驗證項目 |
| 切換操控會把角色放到玩家這邊 | `refreshActors` 把新角色放到玩家所在位置 | 切換**不移動任何人**：舊角色留在原地繼續生活；新角色在同一地點就地接手，在別的地點就用雲朵轉場過去（`WorldUI.travel` 新增 `pos`／`sw`）；只有「休息中」的角色才出現在你身邊；坐摩天輪時拒絕切換 | v16 2a、2b |
| 左上角資訊少又不好切換 | 只有頭像、名字、星幣 | **名牌卡**：心情色環、操控模式小圖示、「地點・在做什麼」、需求偏低才浮出的小圖示、其他角色的小頭像（點一下切換；有人在別處／聊天時有小點）；名牌上左右滑＝切換，長按＝操控模式 | v16 3a–3c |
| 買東西、撿東西要先走過去 | `goThen` | 商店、櫃台、菜圃、採集點、撿東西、摘花、路牌改成立刻完成（`App.direct`）；撿到食物／玩具跳出「現在吃／喝／玩」（`App.offerUse`，走原本的 `OC.Use`，不做第二個庫存）；設定「買東西、撿東西要走過去」可以回到舊做法；角色自己的活動（坐下、釣魚、料理、遊樂設施）仍會走過去 | v16 4a、4b |
| 請求／習慣／事件太頻繁 | 各自有計時器，沒有共同上限 | `OC.Budget`（`life/budget16.js`）：請求、來訪、會問你問題的事件共用一個上限，要「實際玩了 N 分鐘」**且**「遊戲時間過了 M 分鐘」都到才輪到下一個（安靜 40 分／普通 20 分／熱鬧 8 分）；請求同時最多 1 個（熱鬧 2）；習慣每 7 個遊戲日才看一次，結果合成一封信；不急的事寫進**信箱**（右上角鈴鐺、手機的「信箱」）；事件間隔跟著熱鬧程度；設定新增「熱鬧程度」 | v16 5a–5c |
| 只是查看關係就會建立紀錄 | `Mind.rel` 讀不到就新增 | 讀取回傳一個暫時的空紀錄，第一次寫入（或碰 `shared`）才存進 `life.rel` | v16 6 |
| 季節和生日只能跟著手機日期 | — | **日曆**（`Clock.cal`）：遊戲曆（預設）一年＝春夏秋冬各 28 天（112 天）、一週 7 天（第 6、7 天週末）；實時曆＝手機日期。生日可以寫「春 12」或 3/14；節日、島報、日期顯示、生日蛋糕 key 跟著日曆。換季時寄信並提示下次開啟換景色（著色器規則不變，另有「現在換季」按鈕） | v16 7a–7c |
| 存檔 | — | v8；`migrateV7`（日曆從原本的季節接續、其餘新欄位用預設值）；v1–v7 都能升級 | v16 8 |

## 未驗證／未完成（誠實標示）
- **手機實機沒有驗證**：兩段式繪製在實機 GPU／WebView 的效能與相容性（我只在軟體渲染的 Chromium 量過，數字不代表手機）；角色 ×2.5 的耗電；名牌卡左右滑、大小框的拖曳手感。
- 兩段式繪製只在 WebGL 2；不支援時角色仍是單段（較糊，但不會壞）。
- 大小框的拖曳只用程式事件測過資料，沒有用手指在實機操作。
- 實時曆下年齡成長會很慢（這是兩種日曆的真實代價）；年齡系統本身在 16.1。
- 16.1 起的內容（開局多角色與關係、意願模型、對話引擎、住處…）**還沒做**。
