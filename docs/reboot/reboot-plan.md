# OC Shimeji 重構（Reboot）開發計畫

> 狀態：**計畫書，等待玩家確認**（第十節列出需要你決定的事）。確認之前不動任何程式碼。
> 預設角色圖：`docs/reboot/cinnamon-roll.png`（3072×3072、透明背景 RGBA，玩家提供的原創角色「肉桂捲」）。

## 〇、前提與原則

### 重構前提（最高優先）
1. **歸零**：舊的程式碼、存檔格式、角色資料**全部不沿用**。
   - 舊版本只留在 git 歷史裡（標籤 `legacy-0.17.3`），新專案不讀舊存檔、不轉換。
2. **定位**：自主生活模擬（觀察系）＋深度桌寵。
   - 玩家匯入自己的原創角色（OC），日常照顧、互動、看牠們自己過日子。
3. **沒有捏臉**：沒有「拼五官、拼身體部件」的捏臉或紙娃娃系統。角色的**外觀**來自匯入、用內建繪圖工具自己畫，或選預設角色；**外觀以外的一切**（個性、聲音、說話、作息、喜好、關係、背景故事…）都可以深度自訂（第十二節）。
4. **Android 手機優先**：
   - 觸控操作；
   - 系統懸浮窗；
   - 背景省電；
   - 各種螢幕比例。

### 參考作品怎麼用
只取**設計原則**：節奏、回饋感、系統之間怎麼互相影響。**不使用**任何參考作品的角色、名稱、Logo、介面圖形、地圖、音效、文字或素材。所有美術與聲音都是原創。

| 參考 | 取用的原則 |
|---|---|
| 角色觀察屋 | 放進來就會自己生活；以「看」為主的視角；匯入門檻低 |
| Tomodachi Life | 角色之間無厘頭的自主社交；性格的化學反應；角色帶著煩惱來找玩家 |
| inZOI／The Sims 4 | 需求值；物件「廣告」自己能滿足什麼需求（smart object）；自主 AI；生活節奏 |
| 集合啦！動物森友會 | 現實時間同步；溫暖的小鎮氛圍；佈置住宅；每天都有一點新東西 |
| 任天堂整體 | 圓潤、柔和、高可讀性；每個操作都有回饋（聲音、彈跳、粒子）；很少的文字 |

### 從舊版學到、這次一開始就要做對的事
這些教訓保留（不是保留程式碼）：
- **一個模擬、一個時鐘**：生活只由一個確定性的模擬核心推進；畫面、桌寵、背景都只是它的觀看者。
- **效能預算先定**：舊版平均約 20 fps 的教訓 → 每個場景有繪製次數、記憶體、耗電的上限，自動化測試檢查。
- **桌寵不是第二套大腦**：舊版桌寵只能讀快照，App 關著時角色是「停住」的。新版讓桌寵與遊戲共用同一個模擬核心。
- **可測試**：每個系統都要能在電腦上（JVM）用單元測試和截圖測試驗證；手機上必須驗證的項目一律明列。
- **不做假功能**；未成年角色絕不涉及戀愛；重大改變（在一起、永久特質）要玩家同意。

## 一、遊戲核心循環與設計支柱

### 1.1 設計支柱（每個功能都要回答「它支撐哪一根」）
1. **牠們真的在生活**：不需要玩家，角色也會吃、睡、聊天、吵架、和好；玩家回來時有故事可看。
2. **你的角色，原汁原味**：匯入的圖保持原樣、動作自然；一張圖就能動，畫得越多越生動。
3. **一直都在身邊**：角色可以跳出 App 到手機桌面陪你；桌面上的事會回到小鎮的生活裡。
4. **溫暖、好懂、手感好**：圓潤柔和的畫面，單手就能玩，每一下觸碰都有回應。
5. **輕鬆，不催促**：沒有懲罰性的倒數；需求低落只會讓角色比較沒精神，不會死掉或逃走。

### 1.2 核心循環

**每一次打開（約 1–5 分鐘）**：
1. 「你不在的時候」：一張卡片，有幾件大事與名場面；
2. 看看大家在做什麼：點角色看狀態；
3. 處理一兩件事：有人肚子餓、有人來商量煩惱、兩人吵架了要不要幫忙；
4. 摸摸、餵食、送禮，角色的反應依個性不同；
5. 把一個角色帶到桌面上，關掉 App。

**每天（現實時間）**：
- 一天的節奏：早上起床、上午活動、午餐、下午、晚餐、夜晚、睡覺；
- 每天的小新鮮事：商店換貨、鎮上的小事件、角色的心願；
- 每天結算關係。

**長期（週、月）**：
- 關係慢慢變化：陌生 → 朋友 → 好友 → 知己；成年角色在玩家同意下可以在一起；
- 收集家具，佈置房子；
- 匯入更多 OC，小鎮變熱鬧；
- 回憶與相簿慢慢累積。

**桌寵循環（白天在手機上）**：
1. 角色在桌面上走、坐、睡、爬螢幕邊緣；
2. 玩家點、摸、拎起、丟出去；
3. 需求低時討食、討摸；點一下就能在桌面上餵牠；
4. 這些全部算進小鎮的生活：被摸過心情變好；在桌面上餓了，回到小鎮也是餓的。

### 1.3 資源與動機（只用溫和的）
- **星幣**：照顧角色、完成小請求、出售收成或作品得到；用來買家具、食物、禮物。沒有付費貨幣。
- **回憶**：每個重要時刻一張卡；相簿與時間線。
- **心願**：角色自己提出的小目標（想吃某道菜、想和誰變好）；達成時有反應與回憶。

## 二、技術選型與 Android 桌寵底層架構

### 2.1 選型比較與建議

| 方案 | 小鎮畫面 | 桌寵懸浮窗 | 共用模擬核心 | 在本環境建置 | 自動化測試 | 評估 |
|---|---|---|---|---|---|---|
| **A. 原生 Kotlin（建議）** | 自製輕量 2D 渲染（OpenGL ES 2.0） | 原生小視窗，同一套渲染 | ✅ 同一個 Kotlin 核心 | ✅ 現有的離線管線 | JVM 單元測試＋JVM 截圖渲染 | 效能、耗電、桌寵整合最好 |
| B. WebView（舊版的做法） | HTML/WebGL | 原生另寫一套 | ❌ 兩套（舊版的問題） | ✅ | Chromium 測試最方便 | 已知效能與「桌寵是快照」問題 |
| C. Godot 4 | 引擎 | 無法把引擎畫面放進多個系統懸浮小視窗 | 部分 | ❌ 需下載匯出模板 | 中 | 不適合深度桌寵 |
| D. Unity | 引擎 | 同上，記憶體大 | 部分 | ❌ 無法下載 | 中 | 不適合 |
| E. Jetpack Compose＋原生 | Compose | 原生 | ✅ | ❌ 需要 Google Maven（本環境連不上） | 中 | 環境不允許 |

**建議 A：全部用 Kotlin，不依賴 AndroidX**。原因：
- 桌寵是這個遊戲的核心。懸浮窗只有原生做得好；遊戲與桌寵要用同一個模擬核心，就只能都是原生。
- 2D 角色看板在 2D 世界裡最自然；自製的 2D 渲染器很小、可控、省電。
- 本環境連不上 Google Maven（無法用 AGP、AndroidX、Compose），但現有的離線建置管線（kotlinc／javac → ProGuard desugar → dx/d8 → aapt → 簽章）可以沿用。這是**建置工具**的延續，不是程式碼。

**代價（老實說）**：
- 舊版能在 Chromium 裡用真實觸控測整個遊戲；原生版在本環境**沒有模擬器**。
- 補救：
  - 核心、AI、版面計算都寫成純 Kotlin，在 JVM 上測；
  - 渲染器有 JVM 後端，畫到 `BufferedImage` 做截圖比對；
  - 觸控手勢的判斷是純函式，用錄好的觸控序列測試。
- 真正的觸控手感、懸浮窗、耗電**只能在你的手機上驗證**，每個里程碑都會列出要你試的清單。

### 2.2 模組架構

```
reboot/
  core/            純 Kotlin（不依賴 Android），全部有單元測試
    sim/           確定性模擬：時鐘、需求、活動、AI、社交、事件、關係、經濟、存檔
    anim/          動畫資料、狀態機、程序動畫（一張圖也能動）
    pet/           桌寵行為：物理、邊緣、攀爬、手勢判斷、討食、選單
    world/         地圖資料、導航（格子＋A*）、物件與互動位子
    ui-kit/        版面計算、彈簧動態、主題 tokens（純數值，渲染無關）
    content/       資料檔的讀取與驗證（活動、物件、事件、台詞）
  render/
    api/           渲染介面（畫圖、文字、九宮格、粒子）
    gl/            Android：OpenGL ES 2.0 實作（批次繪製、圖集）
    jvm/           電腦：BufferedImage 實作（截圖測試用）
  app/             Android 外殼
    game/          GameActivity（GLSurfaceView、輸入、UI 圖層）
    overlay/       OverlayService（前景服務）、PetWindow（每隻一個小視窗）
    importer/      檔案選擇、解碼、去背、對齊、預覽
    platform/      通知、鬧鐘、小工具、權限、診斷
  content/         遊戲資料（JSON）：物件、家具、食物、活動、事件、台詞、地圖
  art/             原創美術（圖集來源）、肉桂捲
  tools/           圖集打包、資料驗證、截圖比對、APK 建置腳本
```

### 2.3 一個模擬、三種觀看方式

```
           ┌──────────── core:sim（唯一的真相，確定性、固定步長） ────────────┐
           │  時鐘 → 需求 → AI 決策 → 活動 → 社交／事件 → 關係 → 存檔         │
           └──────┬──────────────────────┬──────────────────────┬─────────────┘
        遊戲畫面（GameActivity）   桌寵（OverlayService）    背景（不在跑）
        看見全部、可操作            看見桌面上的角色         回來時「補算」離開的時間
```

**SimHost**：模擬只有一個實例。
- App 前景時，`GameActivity` 擁有它；
- 只有桌寵開著時，`OverlayService` 擁有它；
- 兩者都在時，共用同一個（同一個行程、同一個物件）；
- 兩者都不在時，**不在背景空跑**。下次開啟時用「補算」推進離開的時間：同一個存檔、同一段時間結果固定，上限 30 天，不給星幣物品。舊版驗證過這個做法可行。

**模擬精度**：
- 畫面上的角色：細的模擬（每 0.2 秒一步，有位置、路徑、動畫）；
- 不在畫面上的：粗的模擬（每 10 遊戲分鐘一步，只有「在哪裡、做什麼」）；
- 桌面上的角色：用細的需求模擬，位置由桌寵物理決定。

### 2.4 Android 桌寵底層

**視窗**：
- 每隻桌寵一個 `TYPE_APPLICATION_OVERLAY` 小視窗，大小＝角色加上一點邊距；
- 泡泡、選單各自是暫時的小視窗；
- **不加全螢幕透明層**（耗電，而且會擋住觸控）；
- 視窗一律 `FLAG_NOT_FOCUSABLE`，不搶鍵盤；
- 觸控穿透模式用 `FLAG_NOT_TOUCHABLE`，透明度 ≤ 0.8（Android 12 起的規定）；
- 位置用 `WindowManager.updateViewLayout`，每幀最多一次；靜止時不更新。

**桌面的「地面」與邊緣**：
- 螢幕底邊（扣掉手勢列、導覽列）＝地面；
- 左右邊＝可以攀爬的牆；頂邊＝可以倒吊；
- 輸入法開著時，地面上移到輸入法上方（用 insets 判斷；拿不到就維持在底邊）；
- 不讀其他 App 的畫面內容（隱私），所以不會站在其他 App 的視窗上。

**權限與前景服務**：
- 「顯示在其他應用程式上層」：在玩家第一次按「帶到桌面」時，先用一張說明卡解釋，再開系統設定頁；
- 前景服務類型只用 `specialUse`（附子類型說明）；
- 通知是常駐的「肉桂捲在桌面上」，附「收回」與「打開小鎮」；
- 先加懸浮視窗、再 `startForeground`（Android 15 的要求）；
- `START_NOT_STICKY`：被系統關掉就停，不自行重啟；
- **不使用**無障礙服務、`QUERY_ALL_PACKAGES`、wake lock。

**「背景保活」的立場（重要）**：
- Android 不允許、Google Play 也不接受用技巧強行保活。新版的做法是**不需要保活**：
  - 桌寵看得見的時候，前景服務合法地讓它活著；
  - 看不見的時候，什麼都不跑，回來時確定性補算；
  - 提醒、通知用系統的 `AlarmManager`（不精確的鬧鐘，不需特別權限）；
- 小米、華為等會額外關掉背景 App 的手機：在設定裡放一頁「讓桌寵更穩定」，依廠牌說明自啟動與省電白名單，由玩家自己決定。**不主動要求**忽略電池最佳化。

**效能與耗電預算**：

| 狀態 | 幀率 | 目標 |
|---|---|---|
| 桌寵移動中、被拖曳 | 30 fps（拖曳時跟手到 60） | 單隻 CPU < 3%（中階機） |
| 桌寵靜止、待機 | 4–8 fps（只有呼吸、眨眼） | 一小時耗電 < 1% |
| 桌寵睡覺 | 1 fps 或靜止圖 | 接近 0 |
| 螢幕關閉 | 0（停止繪製與模擬細步） | — |
| 全螢幕 App 或遊戲時 | 自動收起（可選） | — |
| 小鎮畫面 | 60 fps 目標、30 fps 下限；每幀繪製批次 ≤ 60 | 記憶體 < 250 MB |

做法：
- 角色圖解碼成依顯示大小的圖集（不把 3072px 原圖直接放進記憶體），原圖另存；
- 動畫只在換幀時重畫；
- 小鎮用圖集＋批次繪製；
- 依裝置等級自動調整：解析度、粒子、陰影、同時在畫面上的角色數。

## 三、OC 匯入規格與動畫系統

### 3.1 支援的格式

| 格式 | MVP | 說明 |
|---|---|---|
| **單張透明 PNG／WebP** | ✅ | 最低門檻。所有動作由「程序動畫」表演（見 3.4） |
| **PNG 序列（ZIP 或多選）** | ✅ | `idle_00.png…` 依檔名對應動作；也可以在匯入畫面手動分配 |
| **Sprite Sheet（PNG＋格子或 JSON）** | ✅ | 支援均勻格子（填行列數）與常見的 JSON 圖集格式（frames＋duration） |
| **GIF／APNG／動態 WebP** | ✅ | 解碼成影格，保留每格時間 |
| **Aseprite（.aseprite／.ase）** | 第二階段 | 開放格式；讀取圖層與標籤（tag＝動作） |
| **Live2D Cubism** | 評估後決定 | 需要 Cubism SDK 與授權條款（小型開發者有免費條件，但發布前要簽約）；檔案大、效能成本高 |
| **Spine** | 評估後決定 | 執行庫的使用需要 Spine 授權；同上 |

**OC 套件 `.ocpkg`**（自己的格式，ZIP）：
- `manifest.json`：格式版本、名稱、作者、動作表、錨點、顯示大小、預設性格、授權聲明；
- 圖片；
- `preview.png`。

可以匯出、分享、再匯入；版本升級向下相容。

**驗證**（每一項失敗都要說清楚原因，不能「看似成功」）：
- 單張最大 4096px；工作圖自動縮到 ≤ 1024px（依顯示大小，另存原圖）；
- 單一角色最多 600 格、壓縮後 64 MB；
- 拒絕：損壞的檔案、沒有透明度又無法去背的圖（會提供去背工具）、超過上限的檔案。

### 3.2 匯入流程（手機上 5 步）
1. **選檔**：系統檔案選擇器（不需要儲存權限）；
2. **檢查與去背**：從邊緣灌水去背，可用手指補擦；
3. **取景與錨點**：自動找腳底；手指拖曳調整大小與腳底位置；所有動作共用同一個比例；
4. **分配動作**：自動依檔名或標籤猜；沒有的動作顯示「用程序動畫代替」；
5. **基本資料與性格**：名字、說話方式、5 題性格小問答（或隨機）、喜歡的東西；完成後有一段「搬進來」的小演出。

### 3.3 動畫狀態機

**動作清單**（每個都有「備用鏈」：沒有這個動作就退回下一個，最後一定是 `idle`）：

| 類別 | 動作 | 備用鏈例子 |
|---|---|---|
| 基本 | idle、walk、run、sit、sleep | run → walk → idle |
| 生活 | eat、drink、talk、think、read、play、work、bathe | eat → talk → idle |
| 情緒 | happy、angry、sad、shy、surprised、bored | happy → idle（加程序跳動） |
| 互動 | clicked（被點）、petted（被摸）、held（被拎起）、thrown（被丟）、land（落地）、dizzy | held → idle（加程序搖擺） |
| 桌寵 | climb（爬牆）、hang（倒吊）、peek（偷看）、fall（掉落） | climb → held → idle |

**狀態機的規則**：
- 狀態之間有優先等級（被拎起 ＞ 互動反應 ＞ 情緒 ＞ 活動 ＞ 待機）；
- 一次性的動作播完就回到「底層狀態」（活動或待機）；
- 每個動作的資料：影格、每格時間、是否循環、可中斷點、事件（腳步聲、咀嚼聲、粒子）；
- 切換時 0.15 秒的柔和過渡（縮放與透明的交疊，不是影格混合）；
- 方向：預設畫的是側面，向另一邊走時水平翻轉（可以關掉，給不對稱的角色）；可選背面圖；
- **保證不卡住**：沒有結束時間的高優先狀態（例如被拎起）一定有擁有者；擁有者消失 2 秒後自動回到底層。這是舊版的教訓。

### 3.4 程序動畫層（讓一張圖也活起來）
疊加在影格上：
- **呼吸**：上下輕微伸縮；
- **走路**：上下彈跳＋左右微傾；
- **跳躍**：預備壓扁 → 拉長 → 落地回彈；
- **被拎起**：以抓住的點為支點、依手指速度擺盪（彈簧）；
- **被丟出去**：旋轉＋落地壓扁＋暈眩的星星粒子；
- **情緒**：開心＝小跳、生氣＝抖動＋紅色氣、害羞＝縮小＋紅暈貼紙、睡覺＝慢呼吸＋Zzz；
- **被摸**：被摸的地方輕微壓下＋愛心粒子。

只有單張圖的角色，也有完整的全部動作。玩家畫了某個動作，就用玩家的，程序層只加輕微的修飾。

### 3.5 預設角色「肉桂捲」
- 名稱「肉桂捲」，種族「未知」（玩家可以之後補）；
- 第一版用你提供的單張圖＋程序動畫；
- 圖原樣保留，不重畫、不改色；
- 角色檔案：
  - 性格「好奇、溫和、有點黏人」——這是建議值，可以改；
  - 喜歡：甜點、曬太陽；
  - 說話方式：短句、語尾溫和；
- 定位（玩家指示修正）：**開場時可以選的預設角色**，不是引導員。
  - 開新觀察時，在「選住民」那一步和「匯入」「自己畫」並列；可以選也可以不選；
  - 選了就是一般住民：可以改設定、改動畫、搬走，和其他角色完全一樣；
  - 圖一直內建在 App 裡，之後在任何存檔都可以再加入；
  - 也是匯入功能的範例（可以把肉桂捲匯出成 `.ocpkg` 看格式）。
- 教學不由角色帶：用簡短的情境提示卡（第一次做某件事時出現一次，可關閉、可在設定重看）。
- 之後如果你提供更多動作圖（走路、睡覺…），直接放進肉桂捲的套件就會使用。

## 四、自主 AI 與社交事件系統

### 4.1 需求（8 個，0–100，依遊戲時間下降）

| 需求 | 滿足方式 | 低落時 |
|---|---|---|
| 飽足 | 吃、喝 | 走路變慢、討食 |
| 精力 | 睡、休息 | 打瞌睡、拒絕玩 |
| 衛生 | 洗澡、洗手 | 心情慢慢下降 |
| 社交 | 聊天、一起做事 | 去找人、寂寞 |
| 樂趣 | 玩、看書、興趣 | 無聊、搗蛋 |
| 舒適 | 坐、躺、好的家具 | 坐立不安 |
| 環境 | 漂亮整潔的房間 | 想打掃或出門 |
| 關注 | 玩家的互動（摸、餵、聊） | 討摸、在桌面上找你 |

**心情**是需求、最近事件、天氣、關係的加權結果，會影響說話、動作和選擇。

**沒有懲罰**：不會死、不會逃走、不會生病到無法挽回（生病只是「需要休息幾天」）。

### 4.2 決策：效用 AI＋行為樹

**第一層：效用 AI（選「接下來要做什麼」）**
- 每個物件**廣告**它能做的事和滿足的需求，例如床：「睡覺 精力+60/小時」；
- 每個候選的分數由這些相乘：
  - 需求的急迫度（低的需求權重大幅提高，曲線可調）；
  - 個性（貪吃的人吃東西加分、內向的人社交減分）；
  - 喜好（喜歡的活動加分、討厭的減分）；
  - 作息（晚上睡覺加分）；
  - 距離與排隊（遠的、有人在用的減分）；
  - 最近做過的（避免一直重複）；
  - 隨機擾動（固定種子，結果可重現）。
- 從前幾名中加權抽一個，讓行為像人，不像機器。
- **「為什麼」**：每次選擇都記下前三名與理由，人物卡上看得到（例如「肚子很餓，又剛好在廚房附近」）。

**第二層：行為樹（執行「怎麼做」）**
- 例：吃飯 = 序列[找食物 → 走到冰箱 → 拿 → 走到餐桌 → 坐下 → 吃（動畫）→ 收拾]；
- 每個節點可以失敗（位子被佔、沒有食物）→ 回報給第一層重新選擇，並寫下原因（「本來想吃飯，但冰箱空了」）；
- 可以被打斷（被叫、被拎起、事件），之後依情況繼續或放棄。

**玩家的控制**（每個角色一個開關）：
- **觀察**（預設，完全自主）；
- **建議**：玩家可以排「希望你做的事」，角色依意願接受或婉拒並說原因；
- **操控**：直接指揮，只在玩家想要時。

### 4.3 個性與喜好
- **個性軸**（5 條，−2…+2）：外向／內向、活潑／沉穩、認真／隨性、坦率／含蓄、溫柔／好勝。決定各種分數與說話語氣。
- **特質**（最多 10 個）：資料驅動，每個都有看得到的效果（例如「貪吃」：飽足下降快 20%、吃東西加分、會偷吃別人的點心）。互相衝突的不能同時選。
- **喜歡／討厭的事**（各最多 10）：找人玩、聊天、貼貼、家務、做飯、運動、看書、發呆…
- **口味**：喜歡、討厭的食物，吃了會有反應，也會慢慢發現。

### 4.4 社交：對話與「化學反應」

**社交行為**（約 40 種、10 類）：打招呼、聊天、分享、開玩笑、稱讚、抱怨、吵架、道歉、送禮、邀請一起做事、擁抱、惡作劇…

**意願**：
- 對方要不要接受，由這些決定：關係、個性、心情、需求、旁邊有誰、歷史；
- 反應是光譜（熱情 → 開心 → 普通 → 敷衍 → 婉拒 → 生氣 → 哭了），每種反應都有後果。

**化學反應表**（Tomodachi 式的趣味來源，全部原創設計）：
- 兩人的特質組合會觸發特別的互動；例如「好勝 × 好勝」＝莫名其妙的比賽，「愛照顧人 × 粗心」＝追著叮嚀；
- 一張資料表，每格寫觸發條件、機率、演出、結果。

**話題**：
- 從角色身邊的事產生：剛做的事、吃過的東西、天氣、共同興趣、其他人（八卦）；
- 每人對話題有立場，聊天是一串互相回應；
- 聊得來的變熟，意見不合的會記住。

**關係**（兩個方向分開）：
- 熟悉、好感、信任、心動、衝突；
- 每天結算一次名稱（連續兩天才變）：陌生 → 認識 → 朋友 → 好友 → 知己，也會淡掉；
- 戀愛：只在兩個成年角色、玩家打開戀愛功能時才有；在一起、訂婚、結婚、分手都要玩家同意；**未成年絕不涉及**。

### 4.5 事件系統
- **資料驅動**（JSON）：觸發（時間、地點、需求、關係、旗標）、參與者、步驟（走過去、說話、動作、選擇、鏡頭）、結果（關係、回憶、旗標）。
- **類型**：

| 類型 | 例子 |
|---|---|
| 日常小事件 | 一起看夕陽、分零食、找東西 |
| 化學反應事件 | 特質組合觸發的無厘頭場面 |
| 煩惱（Tomodachi 式） | 角色頭上出現煩惱泡泡，點了牠就說，你選怎麼幫（送東西、給建議、介紹朋友），結果有好有壞 |
| 連續劇 | 用旗標串起來的跨天小故事 |
| 小鎮事件 | 市集、季節活動、天氣 |
| 大事 | 生日、紀念日、告白，用小劇場演出，錯過可以回放 |

- **節奏控制**：
  - 一次只有一個需要玩家看的事件；
  - 有冷卻時間；
  - 「打擾預算」：每小時最多 N 件要你回應的事，其餘寄到信箱；
  - 可以設定熱鬧程度。
- **離開時**：粗的模擬照常發生不需要玩家的事；需要玩家的事等你回來。

### 4.6 確定性與存檔
- 模擬的亂數只來自存檔的種子＋時間；同一個存檔、同一段時間，結果永遠相同（可測試、可預測，也能拿來做桌面通知）。
- 存檔：
  - JSON（版本號、每次升版的遷移函式）＋圖片另存檔案；
  - 自動保存；兩份輪流寫（寫到一半斷電不會壞）；
  - 匯出／匯入成一個 ZIP；
  - 存檔從 `v1` 開始，**不讀舊版存檔**。

## 五、小鎮與住宅場景規劃

### 5.1 視角與畫風（建議，需確認）
- **建議：2.5D 分層插畫風**：
  - 斜俯視、固定鏡頭，可以平移與縮放；
  - 地面、牆、家具都是圖（我們用程式產生＋原創手繪風的圖集）；
  - 角色是匯入的 2D 圖，站在場景裡依深度排序。
- 理由：
  - 2D 的 OC 在 2D 場景裡最協調；
  - 效能好，中低階手機也能 60 fps；
  - 最接近「柔和、圓潤、像玩具」的感覺。
- 另一個選擇是像舊版一樣的 3D 世界：更立體，但效能成本高（舊版 20 fps 的原因之一），2D 角色站在 3D 世界裡也比較難協調。

### 5.2 首發地圖（只有這兩區）

**A. 玩家的家**
- **室內**：
  - 一層、四個房間：客廳、廚房與餐桌、兩間臥室（一間給肉桂捲）、浴室；
  - 每個房間是一個畫面區塊，可以縮放看整層（觀察屋式的剖面視角）；
  - 角色多了可以加蓋房間，擴建是資料。
- **庭院**：小菜園、曬衣架、一張長椅、信箱（收信與包裹）。
- **佈置**：
  - 格子放置家具（拖曳、旋轉、收回、復原）；
  - 牆紙、地板；
  - 家具有互動位子（沙發 2 人、床 1–2 人）；
  - 房間的「環境分數」影響角色心情。

**B. 小鎮中心**
- **廣場**：噴水池、布告欄（今天的小事件、角色的心願）、長椅；
- **雜貨店**：食物、日用品（每天換貨）；
- **家具店**：家具、牆紙、地板（每週換貨）；
- **咖啡館**：點餐、聊天的好地方；
- **小公園**：草地、樹、看雲、野餐。

**移動**：家門口和小鎮之間是一條路。角色自己走過去，有路程時間；玩家點地圖切換畫面。

### 5.3 未來地圖的擴展架構
**一張地圖＝一個資料包**（`content/areas/<id>/`）：
- `area.json`：大小、格子（可走、牆、門）、圖層、出入口、天氣是否影響、開放條件；
- `objects.json`：物件與互動位子、它們廣告的活動；
- 圖集、背景音的設定；
- 選用的 `events.json`（這張地圖專屬的事件）。

**引擎不知道有哪些地圖**：
- 地圖登記表在啟動時讀資料包；
- 未開放的地圖在地圖上明確標示「未開放」，**不做假入口**。

**之後可以加的**（只是方向，不在首發）：海邊、森林、學校、其他小鎮。

### 5.4 時間同步
- **預設現實時間**（動森式）：跟手機時鐘；早上亮、晚上暗、季節依日期。
- 選項：
  - 「遊戲時間」：可以加速；觀察模式最快 60 倍。
- 手機時間往回調：不回溯、不推算，只顯示提示。
- 天氣：依日期與種子決定（不連網），有晴、雨、雲、霧、雪。

## 六、UI/UX 設計規範

### 6.1 視覺語言（任天堂式的原則，原創的實作）
**形狀**：
- 全部圓角（大元件 24dp、按鈕 999dp 膠囊）；
- 按鈕有「下緣厚度」，像實體按鍵，按下時沉下去；
- 不用尖角、細線框。

**顏色**：
- 柔和、溫暖、低飽和的主色，加一個明亮的強調色；
- 白天、夜晚兩套調色盤，同一套設計；
- 文字是深暖棕，不用純黑；
- 對比度 ≥ 4.5:1。

**字**：
- 開放授權的圓體中文字型，數字用圓潤的無襯線字；
- 最少字級 14sp，主要資訊 16–18sp。

**圖示**：原創的「貼紙風」彩色圖示（厚白邊、圓潤）。

**動態**：
- 彈簧（出現時輕微超出再回彈）、0.2–0.35 秒；
- 列表項目錯開出現；
- 減少動態的設定一律尊重。

**回饋**：每個操作都有至少兩種回應（畫面、聲音、震動中的兩種）：
- 點按鈕：下沉＋音效＋輕震；
- 得到東西：彈出卡片＋閃光＋音效；
- 角色被摸：愛心粒子＋叫聲＋持續的輕震。

**聲音**：
- 原創的短音效，即時合成或自己錄製；
- 每個角色有自己的「聲線」（喃喃自語式，不是真的語音）；
- 背景音樂依時段變化。

### 6.2 畫面結構（直向、單手）

```
┌──────────────────────────┐
│ ⓐ時間天氣      ⓑ通知(有才出現) │  ← 只看，不常按（上方難按到）
│                          │
│        小鎮／住宅畫面          │  ← 點角色＝人物卡；點物件＝動作卡（按了才做）
│      （平移、雙指縮放）          │
│                          │
│ ⓒ人物條（頭像橫向捲動）           │  ← 拇指範圍
│ [ 家 ][ 小鎮 ][ ✦ ][ 背包 ][ 手機 ]│  ← 底部導覽，中間＝帶到桌面／觀察
└──────────────────────────┘
```

**原則**：
- 常用操作都在螢幕下方 40%（拇指範圍）；
- 點選 ≠ 執行：點東西先出現動作卡，按了才做，避免誤觸；
- 卡片與選單剛出現的 0.3 秒不接受按壓；
- 單一主要按鈕：每個畫面最多一個主要動作；
- 返回鍵一律「關掉最上層」；全螢幕工具離開時才問是否儲存，從外面關閉不跳確認；
- 觸控目標 ≥ 48dp；
- 長按＝更多選項（一定也有可以點的入口，不只靠長按）。

### 6.3 主要畫面
1. 小鎮／住宅（主畫面）；
2. **人物卡**（點角色）：現在在做什麼與原因、需求、心情、今天的事、和誰怎樣、互動按鈕（摸、餵、聊、送禮、帶到桌面）；
3. **手機**（「日常」中心）：時間線、相簿、好感度、信箱、心願、商店、設定；
4. **匯入工作室**（第三節的 5 步）；
5. 佈置模式；
6. 桌寵中心：誰在桌面上、行為設定、提醒、耗電與權限狀態。

### 6.4 螢幕適配
- 設計基準 360×800dp，支援 16:9 到 21:9、平板與摺疊機（寬螢幕時人物卡變成側欄）；
- 處理瀏海、挖孔、圓角、手勢列（WindowInsets），內容不被遮；
- 字級跟隨系統字體大小（到 1.3 倍不跑版）；
- 深色模式：跟隨系統或手動切換；
- 截圖測試：每個畫面在 4 種尺寸 × 2 個主題 × 2 種字級各拍一張比對。

## 七、分階段開發路線圖

> **已修訂**：第二輪的要求讓範圍變大，里程碑的最新版本在 **12.11**；這一節保留作為各里程碑驗收方式的說明。

每個里程碑都有：
- **驗收條件**（自動測試）；
- **你在手機上要試的事**（我沒有模擬器）；
- APK、報告、推送。

版本號從 `0.1.0-reboot` 開始。

### M0 地基（重構的第一步）
- 標記並移出舊程式（`legacy-0.17.3` 標籤；工作目錄只留新專案）；
- 新的建置管線：Kotlin 模組 → 離線 APK；JVM 測試；截圖比對工具；
- 渲染器（GL＋JVM 兩個後端）、圖集、文字、九宮格；
- 存檔 v1（雙檔寫入、遷移框架）；
- 設計 tokens 與 10 個基本元件（按鈕、卡片、膠囊、彈出卡、列表、分頁、開關、滑桿、提示、對話泡泡）。
- **驗收**：
  - 空白小鎮畫面在 JVM 截圖與預期一致；
  - APK 能安裝、開啟，顯示肉桂捲；
  - 冷啟動 < 2 秒（中階機，**需實機**）。

### M1 垂直切片：肉桂捲的家
- 住宅室內（客廳、廚房、臥室）、5 種家具與互動位子；
- 肉桂捲：程序動畫的全部動作、8 個需求、效用 AI＋行為樹（吃、睡、坐、發呆、洗澡、玩）；
- 觸碰：點、摸（滑動累積）、拎起、丟出、落地；人物卡；
- 現實時間與晝夜；離開補算＋「你不在的時候」卡片；
- 第一次打開的情境提示卡（不是角色帶）。
- **驗收**：
  - 24 遊戲小時的模擬兩次結果相同；
  - 肉桂捲自己吃、睡；
  - 每個動作都能播且不卡住；
  - 60 fps（JVM 計時估算＋**實機**）。

### M2 OC 匯入與動畫系統
- 五種格式（單張、序列、Sprite Sheet、GIF/APNG/WebP、`.ocpkg`）；
- 去背、取景、錨點、動作分配、備用鏈；
- 性格問答、特質、喜好、說話方式；

### M3 桌寵 MVP（核心重點）
- `OverlayService`＋每隻一個視窗（最多 3 隻）；

| 風險 | 影響 | 對策 |

## 十一、完整遊戲系統總表（腦力激盪）

> 所有點子都是**原創設計**；參考作品只提供「什麼樣的感覺好玩」，不照搬任何系統名稱、文字、角色或畫面。
> 每一項標上排入的里程碑：**M1–M5＝MVP**、**1.0**（M6）、**1.x**（之後）、**延伸**（有空再做或要你決定）。
> 排序原則：先做「讓角色看起來真的活著」的，再做「讓你想每天回來」的，最後做「讓內容一直長出來」的。

### 11.1 好玩的來源（設計目標）
1. **驚喜的節奏**：
   - 每次打開至少看到 1 件「欸？」的小事；
   - 每天 2–3 件小驚喜、每週 1 件大事；
   - 由「熱鬧程度」設定控制密度。
2. **故事自己長出來**：
   - 系統之間互相影響。例：下雨 → 兩人困在咖啡館 → 聊到共同興趣 → 變朋友 → 一起做的東西被擺在家裡；
   - 不是寫死的劇本。
3. **個性看得出來**：同一件事，不同角色的反應明顯不同（動作、台詞、選擇）。
4. **玩家是「好鄰居」不是「主人」**：
   - 你給建議、幫忙、照顧，但牠們有自己的意願；
   - 被拒絕也有趣（會說原因）。
5. **收集的是回憶**：最有價值的收藏是發生過的事（照片、名場面、日記），不是物品數量。

## 十二、第二輪：玩家的修正與新增

玩家這一輪的要求（原文重點）：
1. 肉桂捲只是開場可以選的角色，不是引導；
2. 開場可以選家的房型，每種房型有不同的房客限制；
3. 進入遊戲先有多個存檔可以選，或開始新的觀察；
4. 要有非常完整、方便的動畫系統、匯入系統、自訂物品、繪圖、工坊；
5. 每個動作可以選系統預設動畫或玩家做的動畫；
6. 基本上任何東西都可以自己匯入；
7. 高度自訂的角色創建系統（像角色觀察屋、Tomodachi Life、The Sims 4、inZOI），包含關係；
8. 再多 brainstorm。

**和「沒有捏臉」的關係**：
- 這裡的「角色創建」指的是**外觀以外的一切**：個性、聲音、說話、喜好、作息、關係、背景；
- 外觀仍然是匯入、自己畫或選預設角色，**不做拼五官、拼身體部件的捏臉**；
- 如果你其實也想要部件式的捏臉，請告訴我，那會是一個獨立的大系統。

### 12.1 進入遊戲：存檔選單（「觀察日誌」）

**第一個畫面**：
- Logo 之後是存檔列表；
- 每個存檔一張卡：
  - 小鎮名；
  - 最後畫面的縮圖（自動截圖）；
  - 住民的頭像；
  - 第幾天、遊玩時間、最後遊玩時間；
- 最上面一張大卡「開始新的觀察」。

**每個存檔可以**：
- 繼續；
- 改名、換封面（選相簿裡的照片）；
- **複製**：做一份一模一樣的；
- **分支**：從今天開出一個平行世界，看「如果」——兩邊之後各自生活；
- 匯出成一個檔（`.ocsave`）、從檔案匯入；
- 刪除：要確認，無法復原；
- 自動備份：每個存檔保留最近 3 天，可以回到昨天。

**存檔數量**：不限，只受手機空間限制；設定裡有「空間使用」頁。

**存檔之間共用的「收藏庫」**：
- 匯入或畫好的角色、動畫、物品、壁紙、音樂都放在收藏庫，任何存檔都可以拿來用；
- 角色放進某個存檔時，那個存檔裡的牠會照自己的生活成長；收藏庫裡的原版不變；
- 也可以把存檔裡「長大了的」角色存回收藏庫，成為新版本。

### 12.2 開始新的觀察（開場流程）
1. **命名**：小鎮名稱、家的名字；
2. **選房型**：每種房型一張俯瞰圖預覽，標出房間、床位與限制（12.3）；
3. **選住民**：
   - 從收藏庫選；
   - 選預設角色（目前是肉桂捲）；
   - 匯入新的；
   - 自己畫一個；
   - 房型的限制會即時檢查（人數、年齡規則），不符合時說明原因；
4. **安排房間**：誰住哪一間、誰跟誰同房（同房規則見 12.3）；
5. **設定關係**：住民之間的關係圖（12.5），可以跳過，讓牠們從陌生人開始；
6. **入住日**：一段搬進來的小演出（每個人提著行李進門、看看自己的房間、第一句話），然後開始觀察。

可以隨時「之後再設定」，進遊戲後都改得到。

### 12.3 房型與房客限制

| 房型 | 房間 | 最多住民 | 特別的限制與特色 |
|---|---|---|---|
| 單人套房 | 一個開放空間＋浴室 | 1（可以多一位「常客」白天來玩） | 小、溫馨、佈置成本低 |
| 雙人小屋 | 2 間臥室＋客廳＋廚房＋浴室 | 2 | 也可以兩人同一間 |
| 三房公寓 | 3 間臥室＋客廳＋廚房＋浴室 | 4 | 一間臥室最多兩人 |
| 庭院平房 | 3 間臥室＋大客廳＋庭院（菜園、曬衣） | 5 | 有庭院活動、可以養小盆栽 |
| 共居宿舍 | 4 間臥室＋大餐廳＋**兩間共用浴室** | 8 | 浴室要排隊、家務容易起摩擦、熱鬧 |
| 家族大宅 | 5 間臥室＋書房＋大客廳＋庭院 | 10 | 一開始鎖住，住民越多、越熱鬧才解鎖 |

**所有房型共通的規則**：
- 人數上限；臥室與床位（同房、同床依關係與年齡判斷）；
- **未成年**的住民一定要有至少一位成年住民同住；
- **嬰兒**需要有人照顧（育兒是 1.x，預設關閉）；
- 共用設施有容量（一間浴室一次一人 → 早上排隊是故事來源）；
- 每種房型有自己的「個性」：
  - 宿舍的家務糾紛比較多；
  - 套房的人比較常出門；
  - 平房的人常在庭院。

**之後換房型**：
- 「搬家」：選新房型 → 住民各自表態（想搬、捨不得、要求自己的房間）→ 搬家日；
- 家具全部帶走，放不下的進倉庫。

**房型是資料**：之後可以加新房型，也可以匯入玩家自己畫的房型（12.8）。

| 分頁 | 可以設定的 |
|---|---|
| 外觀 | 匯入（第三節所有格式）、自己畫、選預設角色；大小、腳底、方向；**表情差分**（為每種情緒各放一張臉或全身圖，選用）；代表色 |
| 基本 | 名字、暱稱、代名詞（他／她／牠／祂／自訂）、年齡與人生階段、生日、身高（影響畫面上的大小）、物種（自由填寫＋特徵標籤，例如「怕水」「會飛」，有實際效果）、標籤 |
| 聲音與說話 | 聲線（音高、速度、音色、明暗，可以試聽；或匯入自己的聲音片段）、說話風格（正式、隨性、可愛、冷淡、文青…）、語尾、口頭禪（多個）、不說的字、怎麼稱呼每個人、怎麼打招呼、**說話測試**（輸入情境，看牠會怎麼說） |
| 個性 | 5 條個性軸；特質（最多 10，分 5 類，每個寫出實際效果、衝突的不能同選）；**小怪癖**（最多 3，可以自己組合）；**價值觀**（最看重：家人、自由、成就、和平、樂趣、美…，影響選擇）；情緒反應強度（容易哭、容易生氣、容易害羞） |
| 喜好 | 喜歡／討厭的事（各最多 10）、食物口味、顏色、季節、天氣、興趣、怕的東西、夢想 |
| 生活 | 作息（起床、睡覺、午睡）、賴床／熬夜傾向、衛生習慣、房間偏好（整齊、亂、要有植物…）、操控模式（觀察／建議／操控） |
| 關係 | 和其他住民的關係（12.5）；對玩家一開始的態度（陌生、親近、害羞…） |
| 背景故事 | 自由文字；**重要回憶**（寫下幾件過去的事，牠聊天時會提起）；**秘密**（信任夠高才會說出來） |
| 能力 | 起始技能（一筆點數自由分配） |

**輔助工具**：
- **性格問答**：10 題，自動填好個性、特質、喜好；
- **隨機**：保證不衝突，可以鎖住想保留的欄位；
- **原創範本**：例如「溫柔的大姊姊」「嘴硬心軟」「天然呆」，套用後再改；
- **從另一個角色複製設定**；
- **相容性提示**：例如「怕吵＋共居宿舍＝會常常不開心」，只提醒、不阻止；
- 復原／重做、草稿自動保存、離開時沒存會提醒。

**之後的改變**：
- 玩家隨時可以改任何設定；
- 角色自己的改變（新的特質、習慣、興趣）一律先問你，同意才生效。

### 12.5 關係設定
- **關係圖編輯器**：
  - 拖一條線連兩個角色；
  - 兩個方向分開設定：A 怎麼看 B、B 怎麼看 A（單戀就是這樣表現）；
- **每條線可以設定**：
  - 關係：陌生、認識、朋友、好友、知己、家人（父母、兄弟姊妹、表親…）、對手、前任、戀人／伴侶（只限兩個成年角色、需要打開戀愛）、自訂名稱；
  - 身分：室友、同學、同事、青梅竹馬、師徒…；
  - 相處標籤：愛拌嘴、互相照顧…（最多 3）；
  - 合拍度；
  - 起始數值（熟悉、好感、信任、心動、衝突，也可以只選「很好／普通／不好」）；
  - **共同的背景故事**（兩人都記得，聊天會提起）；
  - **鎖定**：不會被生活自動改變。
- 之後在遊戲裡，好感度頁與關係網都能再改。

### 12.6 創作套件（繪圖、動畫工作室、自訂物品、工坊）

**繪圖工坊**：
- 圖層：新增、隱藏、透明度、合併、重新排序；
- 筆刷：
  - 鉛筆、沾水筆、馬克筆、噴槍、水彩、橡皮擦、填色、漸層；
  - 筆壓（觸控筆）、防手震；
- 對稱繪圖（左右、放射）；
- 調色盤＋滴管；存自己的色票；
- 選取、移動、縮放、旋轉、翻轉；
- 兩指縮放、平移、旋轉畫布；
- 匯入圖片當圖層或描圖底稿；
- 畫布範本：角色（1024）、物品（512）、壁紙（可無縫拼接）、地板、貼紙；
- 復原／重做 100 步、自動保存草稿；
- 匯出 PNG、直接存進收藏庫。

**動畫工作室**：
- 左邊是動作清單（待機、走路…），每個動作旁邊有開關：**系統預設／我的動畫**（12.7）；
- 時間軸：
  - 每一格可以設不同的停留時間；
  - 複製、刪除、拖曳排序；
  - 循環、播一次、來回播；
- **洋蔥皮**：看得到前後幾格，直接在格子上畫（和繪圖工坊同一套工具）；
- 每格的腳底錨點；一鍵自動對齊整個動作；
- **影格事件**：在某一格放腳步聲、音效、粒子（愛心、汗滴、星星）；
- **預覽**：在試播舞台、在家裡、在手機桌面上（桌寵預覽）播放；
- 程序動作層的開關（呼吸、彈跳、擺盪）；
- 從另一個動作複製；左右鏡像；
- 批次匯入：一次選很多檔，依檔名自動分到各動作；
- **狀態機檢視**：看每個動作的備用鏈，沒有的動作現在會用什麼代替。

**自訂物品編輯器**：
- 種類：家具、裝飾、食物、飲料、禮物、玩具、壁紙、地板、地毯、植物、貼紙；
- 圖：匯入或畫；可以有正面／背面／側面；
- 家具：
  - 佔地格子；
  - **互動位子**（在格子上點出坐、躺、用的位置與方向）；
  - 它「廣告」什麼：滿足哪些需求、提供哪些活動（坐、睡、看書、玩…）；
  - 系列名稱（系列加成）；
- 食物：口味類別、冷熱、飽足、喜歡的個性；
- 禮物：哪些個性或喜好會喜歡；
- 價格、分類、標籤、說明文字；
- 存檔前自動驗證（例如沒有互動位子的床會提醒）。

**工坊**（讓創作進入生活）：
- **委託製作**：你設計好的物品，交給有手作技能的角色做；要材料與時間，做好後放家裡、送人或上架；
- **小鎮市集攤位**：上架你和角色做的作品，其他角色會來逛、買、評論（只是遊戲裡的星幣，不是真錢）；
- **作品集**：每個角色和你自己的作品，有銷量與評價。

**其他編輯器**：
- 自訂台詞（情境＋條件）；
- 自訂小怪癖（動作＋台詞＋時機）；
- 自訂日常事件（積木）；
- 自訂節日（日期、裝飾、活動）；
- 房型編輯器（格子上畫牆、門、窗、房間；1.x）。

### 12.7 動畫來源：系統預設或我的
- **每個角色的每個動作**都有一個開關：系統預設、我的動畫；
- 角色層級的快速切換：
  - 全部用系統預設；
  - 混合（有我的就用我的，沒有就用預設）——新角色的預設值；
  - 全部用我的（沒有的動作就不播、退回待機）；
- **系統預設動畫**：用角色的待機圖做程序動畫（第 3.4 節），沒畫任何動作的角色也完整；
- 可以在動畫工作室並排比較兩者；
- 桌寵也用同一個設定。

### 12.8 什麼都能匯入

| 東西 | 格式 | 用在 |
|---|---|---|
| 角色外觀與動作 | PNG、WebP、PNG 序列、Sprite Sheet、GIF、APNG、動態 WebP、`.ocpkg`（之後：Aseprite） | 住民、桌寵 |
| 表情差分 | PNG／WebP | 情緒時換臉或換全身 |
| 物品、家具、食物、禮物 | PNG＋在編輯器填屬性；或 `.ocitem` | 家、商店、工坊 |
| 壁紙、地板、地毯 | 可拼接的 PNG | 佈置 |
| 照片 | JPG／PNG | 相框、壁紙、存檔封面 |
| 音樂 | MP3、OGG、WAV（單首 ≤ 10 分鐘） | 家裡的收音機或唱片機、存檔的背景音樂 |
| 角色聲音 | 短的 WAV／OGG（每段 ≤ 3 秒） | 取代合成的聲線（開心、生氣、打招呼…各放幾段） |
| 台詞、事件、節日、小怪癖 | JSON（也可以在編輯器做） | 生活 |
| 房型 | JSON 或房型編輯器 | 開場與搬家 |
| 整個存檔 | `.ocsave` | 備份、換手機 |
| **內容包** | `.ocmod`：把以上任何東西打包在一起 | 分享一整套主題 |

**安全與品質**：
- 不接受任何可以執行的程式碼；匯入的資料只是資料；
- 圖片重新編碼（去掉多餘資料）；
- 有大小與數量上限，超過時說清楚；
- 每樣東西有唯一 id，避免衝突（同名的兩個內容包可以並存）；
- 匯入前預覽，失敗一定給原因；
- 收藏庫有「誰在用這個」，刪除前提醒。

### 12.10 這些改動對其他章節的影響
- **第三節**：匯入流程變成角色創建的「外觀」分頁；動畫來源開關見 12.7。

## 十三、第三輪：玩家提供的方向＋更多點子

> 玩家這一輪提供了一份方向文件（五大部分）。下面逐條轉成可以實作的系統，標上排入的里程碑，並**老實標出做不到或要變通的地方**（13.7）。我自己新增的點子放在 13.8。

### 13.1 荒誕幽默與高戲劇性的社交（Tomodachi 式精神，原創實作）

**煩惱諮詢與介入（擴充 D-01）**
- 頭上的氣泡分顏色與圖示：
  - 想交朋友、想告白（只限成年＋戀愛開啟）、想吵架、肚子餓、做了惡夢、有心事、想要東西、無聊；
- 點氣泡後你可以：
  - 選一個建議（每次 2–4 個，依情況產生）；
  - 選牠要說的台詞；
  - **自己打一句話讓牠說出口**：套上牠的說話方式（語尾、自稱），不能違反禁用詞與年齡規則；
- 結果有好有壞，依對方的個性與關係決定，事後兩個人都記得是你出的主意。

**誇張表情與舞台演出**
- **大頭特寫**：重要的對話切到兩人的特寫鏡頭（左右各一）。
  - 特寫取自角色圖的臉部範圍：匯入時框一次，之後自動；
  - 有表情差分就用差分。
- **誇張表情效果**：疊在角色圖上的原創特效，不改原圖：
  - 石化：變灰＋裂紋；
  - 燃燒：火焰粒子＋背景變紅；
  - 冒愛心、黑線、汗滴、怒氣符號、靈魂出竅、閃閃發亮、震驚放射線、冷風；
- **擬聲語**：每個角色的合成聲線（N-02）＋畫面上的擬聲字（「噗」「咚」「啪嗒」）；
- **舞台運鏡**：推近、拉遠、搖晃、慢動作、分割畫面、聚光燈；
  - 由事件與小劇場的步驟控制；
  - 減少動態的設定下改成淡入淡出。

**跨世界觀話題碰撞**
- 每個角色的標籤（13.2）帶有一組「概念」，例如：
  - 劍修：御劍、宗門、閉關；
  - 社畜：加班、通勤、報表；
  - 吸血鬼：血、日光、棺材；
  - 肉桂捲：甜、捲、烤箱；
- 兩人聊天時，系統從雙方的概念配對，套用原創的「碰撞句型」，產生認真討論荒謬問題的對話，例如：
  - 「御劍飛行算不算無照駕駛？」
  - 「草莓大福可以算是一種血液代餐嗎？」
- 這是**資料驅動的離線產生**（概念表＋句型表），不連網、不用線上 AI；
- 句型分類：
  - 認真定義（X 算不算 Y）；
  - 互相比較（X 和 Y 哪個比較累）；
  - 經驗交換（我那裡都是用 X 解決 Y）；
  - 誤會（把 X 聽成 Y）；
- 雙方的立場依個性產生：一個認真、一個吐槽，或兩個都很認真。

**動態人際關係網（擴充 C-04、C-09）**
- 除了階段之外，關係可以帶「風味標籤」，由長期的互動統計自動產生，你也可以手動加：
  - 死黨、宿敵、單戀、雙向暗戀（兩邊都不知道對方也喜歡，只限成年）、商業互吹、相愛相殺、莫名其妙絕交又火速和好、師徒、飯友；
- **奇怪的小鎮社團**：
  - 三人以上有同一個小癖好或常一起做某件事時，自動成立社團，名字由句型產生（「深夜偷吃布丁同盟」「雨天發呆研究會」）；
  - 有定期聚會、社規、入社與退社的小劇場。

- **專屬活動**：只有帶這個標籤才會做的事（劍修：庭院打坐、練劍；社畜：半夜抱筆電嘆氣、喝黑咖啡）；
- **作息修正**（夜行性、不睡覺）；
- **環境反應**（吸血鬼：白天出門自動撐黑傘、躲陰影；怕水：繞過水窪）；
- **需求修正**（吃很多：飽足下降快）；
- **話題概念**（13.1）；
- **專屬台詞**；
- **相容性**：例如「怕光＋喜歡曬太陽」會提示矛盾。

- 可以匯出成內容包分享（「東方玄幻設定包」）。

**沒有專屬動畫時**：

- 你可以在動畫工作室為它畫專屬動畫。

### 13.3 精緻動畫、細節敘事與玩家自創劇本

**分段動作與情緒疊加（擴充第三節）**
- 每個動作可以分成**起手、循環、收尾**三段，例如：坐下 → 坐著 → 站起來；
  - 沒有分段的動作，系統用程序過渡補上；
- **走路的情緒疊加**：同一個走路，依心情疊加不同的步態：
  - 開心＝蹦跳；
  - 低落＝垂頭、拖步、慢；
  - 生氣＝快而重；
  - 害羞＝縮著；
- **邊走邊做**：手上可以拿東西（麵包、書、傘），道具圖疊在角色的手部錨點；匯入時點一次「手的位置」。
- **部位標記與網格變形（給單張圖的角色）**：
  - 匯入時用手指圈出頭、耳朵、尾巴、身體；
  - 系統依這些部位做網格變形：耳朵抖動、尾巴擺動、頭部轉向、身體呼吸；
  - 這不是完整骨架，但讓一張圖的角色動得細很多；
  - 不圈也能用（就是第 3.4 節的整體程序動畫）。
- **動作風格模組**：可愛風、高冷風、元氣風、慵懶風，改變所有程序動作的節奏與幅度。每個角色選一種，也可以依心情自動切換。

**觀察日誌與心理獨白**
- 點角色或打開觀察紀錄，除了「正在看書」，還有一段**細節描寫**，例如：
  > 《基礎劍法》翻到第 12 頁，他在空白處偷偷畫了一隻睡著的肉桂捲，嘴角微微上揚，看來一個字都沒看進去。
- **怎麼做到**（離線）：
  - 描寫由「場景片段」拼成：活動、物件、正在想的人（依關係與最近的記憶）、心情、標籤、天氣、時間；
  - 每種活動有多組原創句型；
  - 片段只用真的存在的東西：真的在讀的書、真的認識的人、真的發生過的事。
- **心理獨白**：情緒變化大的時候（被稱讚、吵架後、收到禮物），在人物卡留下一句內心話；你可以設定只有在觀察模式才顯示。
- **記憶碎片與因果**：
  - 每個角色記得誰送過禮物、誰搶過零食、誰在牠難過時陪過牠；
  - **恩情與記仇帳本**：數天後主動回禮，或「報復」（無害、可愛的：藏起對方的點心、在對方的布丁上寫名字）；
  - 原諒的速度依個性；
  - 報復與回禮都寫成事件，你看得到前因後果（時間線會把兩件事連起來）。

**自創事件與劇本（UGC 核心，擴充 M-05、M-06）**
- **積木編輯器**（不用寫程式）：
  - 觸發：時間、日期、天氣、地點、特定角色、關係或好感範圍、標籤、心情、旗標；
  - 演出：走過去、面對、說話（可指定特寫）、動作、表情特效、運鏡、音效、等待、選項（玩家選）；
  - 結果：情緒、關係、回憶、旗標、物品（只能是遊戲內的、透過唯一的交易流程）。
- **文字劇本格式**：
  - JSON，另有一種好寫的純文字格式（類似劇本：`[角色] 台詞`、`@動作`、`#條件`）；
  - 匯入時轉成積木，兩邊可以互轉；
  - 也接受 YAML 的子集。
- **劇本包**：
  - 打包成內容包（`.ocmod`），裡面可以有事件、台詞、專屬互動、標籤；
  - 匯入前顯示會用到哪些角色或標籤（沒有的話可以對應到你的角色）。
- **驗證**：
  - 沒有能執行的程式碼；
  - 未成年不涉戀愛的規則在劇本裡也強制；
  - 給錯資料會說是哪一行。

### 13.4 四部名作的核心感受融合

**夢境偷窺**（擴充 A-06）
- 角色睡著時頭上有夢泡泡，點進去看一段 10–20 秒的夢小劇場；
- 夢由「白天的記憶＋標籤概念＋荒謬句型」拼成，例如：被巨大的肉桂捲追、在雲上開演唱會、考試忘了帶頭；
- 用夢專屬的濾鏡、漂浮運鏡；
- 惡夢會讓牠醒來不開心（可以安慰）；
- 好夢可以存進相簿。

**小鎮新聞速報與才藝活動**（擴充 D-07、D-09）
- **新聞速報**：發生大事時（告白成功、社團成立、停電），畫面角落跳出播報員式的快報條。播報員是輪值的住民，用牠自己的說話方式播。
- **才藝活動**：
  - 角色自主發起：歌唱、相聲（兩人一組，依關係有默契加成）、最上鏡大賽、料理對決、才藝秀；
  - 住民當評審與觀眾；
  - 結果影響自信與聲望。

**情緒疊加（Moodlets）**
- 心情不是一個數字，而是**多個情緒小卡的疊加**：
  - 每張卡有來源、強度、持續時間，例如「剛出爐的麵包 +2 開心（2 小時）」「踩到水窪 +1 煩躁（30 分鐘）」；
  - 合成出主要情緒與「複雜情緒」的描述（「複雜但滿足」「又累又開心」）；
  - 影響：行為選擇、走路姿態、表情、說話；
- 人物卡上可以看到所有小卡與原因。

**性格衝突火花**
- 相反特質同住或常見面時，產生專屬的摩擦與互動：
  - 潔癖 × 邋遢：偷偷幫收、碎念、爆發、最後立下家規；
  - 社恐 × 話癆：躲、被追著聊、意外變成好朋友；
  - 早鳥 × 夜貓：吵醒、互相遷就；
- 資料表：每組有一串會隨時間推進的階段（摩擦 → 衝突 → 磨合或分開住）。

**生活微行為與連鎖反應（inZOI 式）**
- 微行為池：
  - 照鏡子整理、無聊時滑手機、盯著窗外的雨嘆氣、伸懶腰、把東西放錯地方又找；
  - 主動打掃，或把房間弄亂；
- **連鎖反應**：一件小事觸發下一件。例：打翻牛奶 → 心情差 → 對室友說話衝 → 室友記住 → 兩天後吵架；時間線用線把因果連起來。
- **小鎮聲望**：每個角色在鎮上的名聲（熱心、愛惡作劇、好廚師），由大家的記憶累積；影響別人怎麼對牠、新聞怎麼寫牠。

**治癒的箱庭節奏（動森式）**
- 季節的畫面與聲音：春天花瓣、夏夜煙火、秋天紅葉、冬天下雪（各有原創的環境音與配樂變化）；
- 禮物與回信文化：住民之間、住民和你之間都會送禮、寫回信；
- **佈置小鎮的公共角落**：在廣場、公園的指定位置擺長椅、花圃、路燈、雕像，住民會使用並評論。

**怎麼做得出這麼多又不重複**：
- **組合式內容**：一個事件＝動作 × 物件 × 心情 × 標籤 × 天氣的組合，句子用變數填；同一個「偷吃零食」，貪吃的、愛面子的、吸血鬼的版本都不一樣；
- **冷卻與輪替**：同一個事件短時間內不重複；系統記錄每個人看過什麼；
- **內容製作工具**：事件編輯器（13.3）也是我們自己做內容的工具；每批內容都經過自動驗證（每個事件在測試中至少發生一次、沒有缺的台詞、沒有卡住的角色）；
- **分批增加**：每個版本加一批，報告寫明目前數量與目標。

**角色專屬事件包**：
- 預設角色（肉桂捲）有自己的一組騷動事件，只在牠是住民時發生；
- 玩家也可以為自己的角色做專屬事件包（同一個編輯器）。

### 13.9 這一輪對架構與路線圖的影響

**新的核心系統**（都是 `core:sim` 裡的資料驅動模組，有單元測試）：
1. **標籤系統**：標籤＝效果組合；角色的行為、話題、台詞、作息都從標籤讀，不寫死在程式裡；
